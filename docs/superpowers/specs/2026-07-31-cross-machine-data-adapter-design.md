# Codex Monitor 跨电脑数据适配设计

## 目标

在不改变现有 Vue 界面、Tauri 窗口、托盘和 `CodexStatus` 前端契约的前提下，重构 Rust 只读数据采集内核，使安装版能够适配不同电脑上的 Codex 数据目录、SQLite schema 和近期日志结构。

成功标准：

- 不依赖用户名、盘符、Codex 安装目录或单一固定数据目录。
- 支持 `CODEX_HOME`，并能从当前用户可访问的系统目录中按结构发现候选根目录。
- SQLite 表或列变化时按字段降级，不因一个字段缺失导致整个快照失败。
- 不依赖单个线程保存的绝对 `rollout_path`；可从候选根目录中发现近期有效日志。
- 订阅套餐优先使用更新、更接近服务端额度事件的可信值，避免旧 JWT 将 Plus 覆盖成 Free。
- 点击“刷新”后重新发现来源并更新本应用缓存，而不修改 Codex 文件。
- 缓存和诊断信息不得包含 token、完整邮箱、对话正文或其他凭证。

## 范围

### 保留

- Vue 组件、HUD 布局、圆环与动效。
- `CodexStatus`、`StatusField` 和 Tauri command/event 的前端契约。
- 托盘、窗口生命周期、安装与构建配置。
- Mock provider 和生产环境无可信值时显示 `--` 的规则。

### 修改

- 拆分当前 `real.rs` 中的目录发现、SQLite 读取、日志读取和字段选择职责。
- 让 recon 与运行时使用同一套根目录发现逻辑。
- 将 recon 的结果保存为受限诊断缓存，刷新后立即用新发现结果采集。
- 删除运行时对人工创建 `field-mapping.json` 才能兜底的依赖；保留显式映射能力作为可选来源。

### 不实现

- MITM、TLS hook、证书安装、进程注入或读取进程内存。
- 访问公网或绕过鉴权、套餐、额度限制。
- 任意脚本、写入型 SQL 或修改 Codex 数据。

## 方案比较

### 方案 A：字段候选与可信合并（采用）

每个适配器输出若干 `FieldCandidate<T>`，包含值、来源、观察时间和置信度。聚合器逐字段选择最新且可信度最高的候选。优点是局部失败不会影响其他字段，易于扩展不同 schema；代价是新增几个小模块和较多夹具测试。

### 方案 B：扩大路径扫描并继续使用单一解析器

只增加 `CODEX_HOME` 和更多目录，然后继续执行固定 SQL 与固定日志 JSON path。改动小，但 Codex schema 变化仍会导致跨电脑失败，因此不采用。

### 方案 C：要求每台电脑手工配置映射

通过 recon 报告让用户编辑 `field-mapping.json`。实现简单，但安装后不能直接使用，违背项目目标，因此不采用。

## 架构

Rust 数据采集层拆分为以下边界：

1. `source_discovery.rs`
   - 输入当前用户 home、`CODEX_HOME` 和系统数据目录。
   - 输出去重、存在且只读可访问的 `DataRootCandidate`。
   - 评分只依据目录结构、文件类型和修改时间。

2. `sqlite_adapter.rs`
   - 以 `SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_NO_MUTEX` 打开候选数据库。
   - 先读取 `sqlite_master` 和 `PRAGMA table_info`，再选择已知兼容列。
   - 每个可用字段独立产生候选，不执行写入 SQL。

3. `rollout_adapter.rs`
   - 在候选根目录的受限深度内发现近期 `.jsonl` 日志。
   - 从文件尾部限量读取近期事件，识别额度、重置时间、套餐、速度档位和推理配置。
   - 不缓存对话内容，只缓存字段来源的相对路径、修改时间和结构指纹。

4. `auth_adapter.rs`
   - 只读取本地认证文件中的必要 claims。
   - 用户名和套餐作为候选；套餐置信度低于近期额度事件。
   - token 仅在内存中解码，绝不写入日志或缓存。

5. `snapshot.rs`
   - 汇总所有适配器候选并逐字段选择。
   - 某个来源失败时记录脱敏诊断并继续其他来源。
   - 至少一个真实字段可用时返回 `connected`；只有旧值时返回 `stale`；无字段时返回 `recon-required`。

6. `diagnostics.rs`
   - 将根目录结构指纹、支持的表/列名、日志事件类型和失败原因写入本应用 data 目录。
   - 保存路径时遮盖用户目录前缀；不保存字段原值、token、邮箱和对话正文。

## 数据流

启动或刷新时：

1. 动态发现候选根目录。
2. 对候选文件进行受限结构探测。
3. SQLite、rollout 和 auth 适配器分别生成字段候选。
4. 聚合器按观察时间、来源优先级和置信度逐字段选择。
5. 返回 `CodexStatus`，同时把脱敏诊断缓存写入应用 data 目录。
6. 后续轮询复用根目录缓存；缓存目标不存在或结构指纹变化时自动重新发现。

来源优先级按字段设置：

- 套餐：近期额度事件 > 当前 auth claim > 显式安全映射。
- 模型、推理强度、速度档位：近期活动线程或近期 rollout > SQLite 历史线程。
- 剩余百分比和重置时间：最新有效额度事件。
- 用户名：当前 auth claim。
- 客户端版本：近期线程/rollout 中的版本，取观察时间最新者。

## 错误与降级

- 根目录不可访问：跳过该候选并记录脱敏原因。
- SQLite 缺表或缺列：只缺失对应候选，不中止采集。
- SQLite 被占用：只读连接失败后继续日志和认证来源。
- 日志损坏：跳过无效行，保留同文件内其他有效事件。
- 旧绝对 rollout 路径无效：不使用它作为唯一入口，改为根目录内重新发现。
- 所有来源无值：返回 `recon-required` 和明确中文提示，字段显示 `--`。
- 轮询临时失败：前端继续按既有合并规则保留上次可信值并标记 `stale`。

## 安全限制

- 文件扫描限制：最多 240 个候选文件、深度不超过 6、单个文本文件只读取末尾最多 256 KiB。
- 所有 SQLite 连接只读；SQL 仅来自程序内固定查询模板。
- 不跟随目录符号链接，不扫描其他 Windows 用户目录。
- 诊断缓存只写入本应用 data 目录。
- 路径缓存优先保存相对根目录信息；展示或报告前遮盖 home 前缀。

## 测试策略

- 根目录夹具：默认 `.codex`、自定义 `CODEX_HOME`、嵌套系统目录、无效候选和重复候选。
- SQLite 夹具：完整 schema、缺少单列、替代列名、多个数据库、新旧线程并存。
- 日志夹具：最新额度、多窗口额度、损坏行、无 `token_count`、旧绝对路径和多个近期日志。
- 认证夹具：Plus/Free claim、缺少 claim、无效 JWT，验证 token 不进入诊断。
- 聚合测试：近期 Plus 覆盖旧 Free、字段独立降级、最新观察时间选择和 stale 保留。
- 集成测试：使用临时目录完整生成 `CodexStatus` 与脱敏诊断，不依赖开发电脑真实数据。
- 回归验证：`cargo test`、`npm test`、`npm run build`、`cargo check` 和 NSIS Release 构建。
